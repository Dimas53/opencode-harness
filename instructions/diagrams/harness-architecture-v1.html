Layer breakdown — what's inside each layer
1 · INSTRUCTION
Rules of the Game
The foundation — everything the agent reads before doing anything
AGENTS.md
Main rules file — safety gates, workflow rules, what to never do
Trigger-based docs
Agent updates docs only on specific events — new composable, new Flow, bug fix
Hard Limits + Safety Gates
Never: git push, rm -rf, modify .env. Stop: docker-compose, deployments, SSH, DB migrations
2 · CONTEXT
What the Agent Sees
Documents loaded into context window each session start
PROGRESS.md
Living log of what's done, current bugs, session fixes
roadmap.md
Big picture phases — agent reads this to not dive into wrong phase
MEMORY.md + HARNESS.md
Lessons learned + project constraints and risk levels
3 · TOOLS
MCP Servers
What the agent can actually do — files, git, browser, APIs
filesystem MCP
Read and write any project file — components, configs, docs
git MCP
Commits, history, diffs — agent tracks its own changes
Directus MCP
Full admin access — creates collections, flows, sets permissions autonomously
Chrome DevTools
Reads browser console, network, errors — debugs without screenshots
Playwright MCP
E2E tests, form filling, navigation, screenshots — full browser test runner
context7 + websearch
Live documentation lookup and web search — always current APIs
4 · LOOP
Execution Cycle
Think → Do → Verify → DoD → Commit — skill-based workflow discipline
Skill-based workflows
Brainstorm, spec, plan, implement, TDD — each phase has a dedicated skill
One concern at a time
Learned the hard way — simultaneous changes = unpredictable rollback
DoD before every commit
Definition of Done runs first — SESSION SCAN, docs, JSDoc, tests, safety, skill feedback
5 · MEMORY
Trigger-Based Docs
Agent writes docs when specific events happen, not on schedule
PROGRESS.md
Updated on every bug fix, feature complete, or session end
MEMORY.md
Accumulates workarounds, lessons learned across sessions
docs/specs/ + architecture
Feature specs and architecture docs created per change type (DoD)
git log + memory/YYYY-MM-DD.md
Structured commit messages + daily workaround notes
6 · SUBAGENTS
Intelligence Tools
Specialized models and tools called for specific subtasks
context7
Pulls live docs for Nuxt, Directus, Vue — always gets current API, not training data
sequential-thinking
Forces step-by-step reasoning before jumping to implementation
7 · VERIFICATION
Quality Gates (DoD)
Checks that run via Definition of Done BEFORE every commit
SESSION SCAN
List everything created/modified/deployed this session
Docs per change type
Schema change → docs/schema.md, new feature → docs/architecture/, etc.
JSDoc + Tests + Safety
JSDoc for new composables/routes, run test suite, check no Cyrillic/leaked secrets
Skill feedback
Note skill issues in memory/YYYY-MM-DD.md — human decides whether to update SKILL.md
8 · SANDBOX (PLANNED)
4-Layer Security Isolation
Architecture plan in notes/SANDBOX_ARCHITECTURE.md — not yet implemented
Layer 1 — Sandbox DB
Agent works with schema-only copy in isolated Docker container — no real data
Layer 2 — .agentignore
Blocks access to prod credentials, backups, PII fields (file + field-level)
Layer 3 — LLM Guard
Anonymizes PII before sending to model, scans responses for data leaks
Layer 4 — Audit Layer
Logs what agent read and sent — metadata-only, answerable to auditor
9 · SKILLS
Knowledge Loaded on Demand
Agent reads relevant skill files before starting any task in that domain

session-start / session-end / dod
Agent boot sequence, session closure, Definition of Done checklist
code-review · codebase-health-check
PR review rules and architecture audit — DRY violations, refactoring opportunities
Process: brainstorm → spec → plan → implement → TDD
brainstorming, spec-driven, planning, incremental-implementation, TDD, grill-me, interview-me, premortem, doubt-driven
