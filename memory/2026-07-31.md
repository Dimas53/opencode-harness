# Session 2026-07-31 — dod.sh docs-lag self-deadlock

## Workarounds / Fixes

### docs-lag check deadlocked the docs commit itself
- Symptom: pre-commit hook blocked EVERY commit once docs lag exceeded 3,
  including the docs commit that would reset the lag.
- Root cause: step 3 counted lag from git history
  (`git log --oneline -- docs/` vs HEAD). The pre-commit hook runs BEFORE the
  commit is created, so HEAD still had the old docs commit and lag stayed > 3
  for the docs commit too. Catch-22.
- Also confusing: commits updating PROGRESS.md / memory/ do NOT count toward
  the docs-lag check (only files under `docs/` do).
- Fix: in PRE_COMMIT mode, if `git diff --cached --name-only` contains files
  under `docs/`, step 3 passes ("Docs updated in this commit — lag resets").
  Non-docs commits with lag > 3 still fail — hook is not weakened.
- General lesson: any history-based check in a pre-commit hook must also look
  at the staged tree, otherwise the commit that fixes the condition is itself
  blocked.
