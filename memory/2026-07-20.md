# 2026-07-20 — Directus MCP: per-project generated config

## Lesson: per-project `opencode.jsonc` from `.env` beats a global MCP for multi-project
- OpenCode's project-level `opencode.jsonc` FULLY OVERRIDES the global config.
- A single global `directus` MCP server means switching the URL requires restarting
  OpenCode; with 3 projects open that means exiting ALL sessions. Painful.
- Solution: no `directus` in the global config. Each project generates its own
  gitignored `opencode.jsonc` from `.env` via `scripts/gen-opencode.sh` (wired into
  `make start`). Three projects = three independent MCP servers. Just switch windows.

## Lesson: never put `DIRECTUS_STATIC_TOKEN` in docker-compose.yml
- A static token in docker-compose.yml is a secret committed to the repo — wrong.
- A proper user-level token (MCP User with an assigned role + App Access) is enough;
  the `DIRECTUS_STATIC_TOKEN` env on the Directus container is unnecessary. Confirmed:
  after removing it and restarting Directus, the MCP `/mcp` endpoint still
  authenticates with the user-level Bearer token.

## Gotcha: OpenCode MCP server does not reread config on the fly
- Changing the `url` of an MCP server in the config does NOT take effect in an
  already-running OpenCode session. The MCP process is long-lived.
- To repoint MCP you must fully Exit every OpenCode session (including other
  projects) and restart. This is exactly why per-project local files are better:
  the file is correct before OpenCode launches, so no mid-session reconfiguration.

## ⚠️ Directus 11: `*` (All Collections) wildcard permission does NOT work
- Verified empirically: a `*` CRUD grant on the `mcp` policy was created (IDs 56-59)
  but did NOT apply to existing collections. An explicit grant on the same
  collection (`mcp_test_2`) worked immediately.
- So `*` is NOT a usable "give everything" shortcut in Directus 11.
- Two working options instead:
  - **Local/dev:** enable **Admin Access** (`admin_access: true`) on the `mcp`
    policy → full access to everything, including not-yet-created collections.
  - **Production / shared:** explicit grant per collection (Settings → Access
    Policies → mcp → Collection Permissions → + Add Collection → specific one).
- Recorded in `instructions/directus-mcp-setup.md` (Step 2a warning + "Granting
  access to your own collections" section).
- **Follow-up / TODO for production:** when we move the `mcp` policy to a shared
  or production Directus instance, we must REMOVE `admin_access` and replace it
  with explicit per-collection grants (least privilege). Do not ship admin_access
  to prod.
